### 10-1. 원격 감시 설정

**정의**
Android 앱에서 감시 조건을 원격으로 바꾸면 YOLOv5 Edge가 이를 반영해 검출·등록 동작을 조정하고, 앱에서 Edge의 접속 상태를 확인할 수 있는 기능이다.

**설명**
기존 검출 방식은 오검출이 깜빡일 때마다 같은 객체를 다시 등록하는 문제가 있었다. 실제 웹캠 테스트에서 75초 동안 게시물이 58건 생성되어, 현장에서 코드를 고치지 않고 앱에서 감시 조건을 조정할 수 있도록 이 기능을 추가하였다.
앱의 감시 설정 화면에서 감시 ON/OFF, 신뢰도 임계값(0.25~0.90), 재등록 대기시간(0~3600초), 감시 대상 클래스(80개 중 선택)를 바꾸고 저장하면 설정이 Django 서버에 저장된다. 범위를 벗어난 값은 서버가 거부한다. YOLOv5 Edge는 5초마다 서버에 접속을 알리면서 최신 설정을 받아 오므로, 앱에서 바꾼 설정이 5초 안에 반영된다.
반영된 설정에 따라 감시 대상이 아니거나 신뢰도가 임계값보다 낮은 검출은 무시하고, 감시 OFF이면 검출은 계속하되 게시물과 영상을 올리지 않는다. 같은 객체가 재등록 대기시간 안에 다시 나타나면 등록하지 않으며, 서버에 연결할 수 없을 때는 마지막으로 받은 설정으로 감시를 이어 간다.
서버는 Edge의 마지막 접속 시각을 기록하여 15초 이내면 온라인으로 판단하고, 앱 메인 화면 상단에 Edge 온라인 여부, 마지막 접속 시간, 감시 ON/OFF 상태를 표시한다.

**관련증빙** (4장)
- 사진 1. 원격 감시 설정 화면: 감시 ON/OFF, 신뢰도 임계값, 재등록 대기시간, 감시 대상을 설정해 저장하며, 상단에서 Edge 접속 상태를 확인할 수 있다. — `ID10-2_4_앱_설정_대기30초.png`
- 사진 2. 감시 설정 API: 서버에 저장된 감시 설정값과 Edge가 등록한 객체 클래스 목록, 허용된 HTTP 메서드(GET·PUT·PATCH)를 확인할 수 있다. — `ID10-1_서버_감시설정API.jpg`
- 사진 3. Edge 감시 ON/OFF 로그: 감시 ON에서는 객체가 나타나면 영상을 녹화해 업로드(201)하고, 앱에서 감시를 끄면 사람이 다시 나타나도 등록하지 않으며(감시 OFF - person 미등록), 다시 켜면 업로드가 재개된다. — `ID10-2_1_Edge_감시ONOFF로그.png`
- 사진 4. 메인 화면 Edge 상태 표시: Edge 온라인 여부, 마지막 접속 시간, 감시 ON/OFF 상태를 표시한다. — `ID10-2_5_앱_메인_온라인_감시OFF.png`

### 10-2. 이벤트 클립 녹화 및 용량 기준 보관 정책

**정의**
새로운 객체가 감지되면 감지 전후 영상을 녹화해 게시물과 함께 저장하고, 저장 용량이 상한을 넘으면 오래된 영상부터 자동으로 삭제하며, 앱과 웹에서 영상을 재생할 수 있는 기능이다.

**설명**
사진 한 장으로는 침입 전후 상황을 알기 어렵고, 영상을 계속 쌓으면 서버 디스크가 가득 차는 문제를 함께 해결하기 위해 추가하였다.
YOLOv5 Edge는 최근 3초 분량의 화면을 항상 보관하다가 새로운 객체가 감지되면 3초를 더 녹화해 약 6초 길이의 MP4 영상을 만들고, 사진과 함께 서버에 올린다. 영상 인코딩과 업로드는 백그라운드에서 처리하므로 녹화 중에도 객체 검출이 멈추지 않으며, 녹화 도중 새로 나타난 객체는 별도 게시물을 만들지 않고 같은 이벤트에 합친다.
서버는 게시물에 영상을 함께 저장하고, 전체 영상 용량이 상한(기본 200MB)을 넘으면 오래된 영상부터 파일을 삭제하고 만료로 표시한다. 이때 게시물과 사진은 그대로 유지되며, 게시물을 삭제하면 사진과 영상 파일도 함께 지워진다. 증빙을 위해 상한을 0.3MB로 낮춰 실행했으며, 이벤트 6건 중 오래된 3건의 영상이 만료되고 게시물과 사진은 유지됐다.
앱 목록에서는 영상이 있는 게시물과 만료된 게시물을 배지로 구분하고, 상세 화면에서 영상을 반복 재생하며 만료된 경우에는 안내 문구를 보여 준다. 웹 상세 페이지에서도 영상을 재생할 수 있다.

**관련증빙** (5장)
- 사진 1. Edge 클립 녹화 로그: 객체가 감지되면 녹화를 시작하고 감지 후 3초를 더 모아 영상을 만든 뒤 사진과 함께 서버에 업로드(201)한다. 녹화 중 나타난 cell phone은 같은 이벤트에 합쳐진다. — `ID10-4_1_Edge_클립녹화로그` 캡처
- 사진 2. 서버 테스트 결과: 영상 저장, mp4 외 파일 거부, 용량 초과 시 오래된 영상부터 만료·파일 삭제, 게시물 삭제 시 파일 삭제 등 보관 정책 테스트 10개가 모두 통과했다. — `ID10-3_1_서버_클립테스트결과.png`
- 사진 3. API 응답: 오래된 게시물 3건은 영상이 삭제되어 clip: null, clip_expired: true이고, 최근 게시물 3건은 영상 주소가 남아 있다. 만료된 게시물에도 사진은 유지된다. — `ID10-3_2_서버_API_클립_만료.png`
- 사진 4. 앱 목록: 영상이 있는 게시물(▶ 클립)과 만료된 게시물(클립 만료)이 한 화면에 구분되어 표시된다. — `ID10-4_2_앱_목록_클립_클립만료.png`
- 사진 5. 앱 영상 재생: 게시물 상세 화면에서 감지 전후 6초 영상을 재생한다. — `ID10-4_3_앱_상세_클립재생.png` (웹 재생 `ID10-3_3_웹_상세_클립재생.jpg`는 선택)
